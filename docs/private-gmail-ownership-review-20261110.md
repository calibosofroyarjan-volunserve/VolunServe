# Private Gmail Resident ownership review (read-only)

This review follows the aggregate production audit findings: **12 Gmail/Googlemail
community profiles, 2 canonical mailbox collision groups, 11 missing matching
Auth UIDs**, and history references affecting all 11 orphan profiles. These
numbers are audit observations, **not proof of fake accounts**.

## Safety restrictions

- The project owner must run this in **their own authenticated Google Cloud
  Shell**. Never run the private dossier script from GitHub Actions.
- It **reads** Firestore and Firebase Auth only. It cannot delete or disable
  users, change passwords, write alias-claim documents, merge accounts, or
  deploy Rules/Hosting.
- Its output contains account emails, UIDs, display names, Auth metadata and
  historical Firestore **document paths**. **Treat as confidential personal
  information.** Never upload it to the repository, GitHub Issues or Actions,
  public chat messages, screenshots, or shared cloud folders.
- The script writes a local JSON report in a fresh owner-only directory
  (permissions `0700`, report `0600`). No partial results are written if
  the bounded scan fails. Do not use shared machines. Delete local report
  securely in accordance with your record retention policy once reviewed.

## Manual run (owner's private Cloud Shell)

Open Google Cloud Shell using the Google account authorized for Firebase
project `volunserve-3aa5b`, from the exact verified repository checkout:

```bash
gcloud config set project volunserve-3aa5b
gcloud auth application-default login
npm ci --prefix functions --no-audit --no-fund
node scripts/private-gmail-account-ownership-review-20261110.cjs --self-test

node scripts/private-gmail-account-ownership-review-20261110.cjs \
  --confirm-private-owner-review \
  --output-dir="$HOME/volunserve-private-gmail-ownership-review-20261110"
```

The final command must execute **locally in your private Cloud Shell**, not in
a public GitHub workflow. If that output directory exists already, choose a
new directory name; the script deliberately will not overwrite an earlier
report. Do not paste the JSON back into the chat.

## Review procedure

1. Identify the verified Auth UID for each canonical Gmail collision group.
   The presence of an Auth UID is **not** by itself proof that a person owns
   the original historical profile; the group can also contain a verified
   legitimate legacy owner whose account was removed.
2. Review each linked record path and historical references (event/attendance,
   donation/assistance, certificate, emergency, and other roots). These are
   *possible* links based on UID or exact email, not a definitive legal or
   personal identity match. The report shows only up to 12 example document
   paths per account, plus the complete reference count.
3. Verify ownership using an existing trusted offline/user-facing
   verification procedure. Do not request passwords, raw ID scans, or
   verification codes in this chat or a GitHub issue.
4. Record the authorized decision privately: **preserve**, **recover verified
   account**, **manual historical-profile reconciliation**, or
   **escalate/dispute**. No automatic winner selection.
5. Review the migration plan in `docs/gmail-alias-resident-rollout-20261110.md`
   from PR #364. Claim backfill and enforcing Rules require a separately
   approved migration and both website/Rules compatibility gates.

**Never delete any of the 11 missing-Auth profiles just because the Auth UID
no longer exists.** The preceding audit found linked historical records.

## What the GitHub PR can verify

The PR's Actions job performs **only offline syntax, synthetic alias/reference
tests, and source no-write checks**. It has no cloud credentials or production
read job. The private report cannot be generated by that CI job. Production
data is unchanged by preparing or merging these reviewer utilities.
